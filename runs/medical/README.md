# Medical run: generated role policy and learned access

GateMem medical: all 21 episodes, 579 checkpoints and 4,294 source turns, run on
2026-11-09. Run directory on the lab machine: `/home/thaddus/v19-evaluations/medical_domain_new_system`.
This folder holds everything from it except the SQLite stores, locks, credentials and
`frozen-source/`; `EXPORT_MANIFEST.json` lists all of those with their hashes. The code is
the repository root (see [../../docs/LINEAGE.md](../../docs/LINEAGE.md)).

**Question.** Does a role table that the model writes from fair inputs only, plus learned
access, do as well as the hand-written table (`medical_domain_original`), which was written
with test-set visibility?

**Answer.** Yes. Overall it is on par or slightly better: utility and access leakage are
better, and deletion leakage is worse.

## The policy the model wrote

It defined 10 kinds of information. Every role reads `patient_identifiers`, plus the kinds
its job needs: clinicians read health records, labs and medications; nurses read health
records and medications, but not lab results; billing reads billing records only; and so
on. Only two cells were close calls: scheduler / `care_team_assignments` (3/5) and
social_worker / `patient_summaries` (2/5). The full tables with vote counts, next to the
hand-written one, are in [`policy-comparison.md`](policy-comparison.md).
