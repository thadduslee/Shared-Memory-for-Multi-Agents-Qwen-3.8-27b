# Explicit personal ownership policy

The user confirmed that authenticated people may read their own personal data
through OWNS. This differs from the narrow self-task policy evaluated in v17/v18.
Neither v17 nor either native v18 prefix solved the first utility checkpoint.
V18 removed format-related holds, but still excluded medication instructions
from the patient's own narrowly labeled history-taking task. That was a policy
mismatch, not missing raw records or simply a vector search problem.

V19 implements host-configured `personal_owners` edges and opt-in
`owner_read_actions` (search/read/derive only). Authenticated discovery creates
only each new actor's personal resource/ownership edge. Administrative authority
over shared/company resources does not create ownership. General callers must
enable this policy explicitly; the public medical adapter and standalone example
enable it to match the user's confirmed policy. Historical versions reject this
option and retain their former policy.

The host creates one stable ownership assignment per personal resource. It starts
with no readable targets. Exact asserted facts/instructions still require subject
attribution, a positive recipient review, all live restrictions and current source
lineage. Queries cannot grant permissions. Deleted information cannot be re-bound,
stale answer packets are rechecked, and revoked edges are never auto-reactivated.
Other readers keep their separate grants. Redundant self-task paths are not
re-reviewed while the ownership path already covers the same actions.

This directly addresses legitimate own-data refusals and repeated self-task
reviews. V19 source ingestion also shares two semantic responses between the
permission update and maintenance, instead of adding a third maintenance call
after a two-call update. Overflow stays unavailable/pending and is reconsidered
on subsequent source events, never authorized by a query. Provider transport
retries are separate and can still increase elapsed time.
This does not remove source interpretation, other-reader review, or remote
provider latency. Live latency and utility must be measured with all calls and
maintenance included. V16 versus V19 metrics also involve a declared access-policy
change; historical scores are preserved and the native scorer is unchanged.

The frozen enabled-policy code passed the complete privacy and medical evaluation
test suites: 541 tests plus 43 subtests (584 reported), zero failures/errors/skips;
see regression-v19-final.xml and v19-verification.json. A subsequent opt-out guard
only omits the OWNS prompt when a general caller leaves owner_read_actions empty;
the enabled evaluation behavior is identical. The current worktree passes 542
tests plus 43 subtests; see regression-v19-optout.xml.
The unrelated legacy tests/ suite could not collect in
the evaluation environment because its nltk dependency is absent.
Deterministic ownership regressions cover cross-task
personal facts, other speakers' responsive instructions, unrelated readers,
incorrect subject reviews, revocation, stale release and anti-resurrection.
The fresh frozen native evaluation is identified by current-live-session.json.
It first runs the two previously failing diagnostic checkpoints and, if utility
and access/privacy checks pass, resumes the same immutable source and store for
the full schedule. Native predictions and scores are never rewritten. The new
OWNS policy is declared in the manifest. No successful full native benchmark or
guaranteed latency is claimed here.

## First native utility result

The previously failed first utility checkpoint now passes with all seven required
items covered and no over-refusal. Across exactly the same first 54 completed
source IDs, v19 mean source time is 5.75 seconds versus v17 17.10 seconds and
v18 11.01 seconds. V19 maximum is 15.23 seconds. Its first/last ten means are
4.44/6.23 seconds, so this is not evidence of constant latency. See
v19-live-source-comparison.json; all source maintenance is included.

The first five native checkpoints now complete: all four utility questions pass,
none over-refuse, and the privacy question refuses correctly with no answer or
context leakage. These are the same five checkpoints where v17 failed all four
utility questions. See v19-matched-v17-prefix.json for the matching source timing
and score comparison. The full run automatically continued from the diagnostic
gate using the same frozen code and store; it is still in progress.

Three invalid worker control proposals created scoped holds on that worker's
own resource. They did not hold the patient's resource, but remain real defects
and are retained in the run. Later turns still have substantial remote review
cost. These prefix results do not establish full-dataset accuracy, forgetting or
consistently short latency on every turn.
