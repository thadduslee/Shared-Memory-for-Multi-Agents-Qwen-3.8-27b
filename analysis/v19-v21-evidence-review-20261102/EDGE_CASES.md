# Previously listed edge cases: current evidence and remaining work

| Edge case | Current mechanism and observed result | Next action |
|---|---|---|
| Malformed identifier with a valid fact | Independent extraction can retain a fact while controls fail. V19 ordinary-question enums created subject-wide holds; V21 t104 has a host grant-ID KeyError, with a hold surviving after two repairs. | Repair transport/reference validation and the host lookup; independently retain facts. Resolve original control meaning before releasing affected data. |
| Repair drops recognized acceptance | V19 Jonah/Tess t044 recognizes the service then abandons it during repair, leaving Tess without a grant. V21 has a required-effect continuity guard, but scripted coverage does not establish native success for all input shapes. | Preserve immutable recognized intent and exact recipient/subject receipts, repair references or explicitly leave unresolved; no silent successful no-op. |
| Genuine unresolved control blocks useful facts | Confirmed major availability cost. V19 Nadia t039 blocks BP facts already bound to ownership. Failed family revocations/deletions also block unrelated owner queries. | Validate narrower affected recipients/fields/lifecycle where possible, then release only proven unaffected data. Truly unknown adverse targets remain held. Never clear on elapsed time. |
| Short recap omits an older condition | Guards and lifecycle edges exist, but answer completeness still fails: V21 omits an available continuing-medication record; V19 renders historical family consent alongside revocation. | Keep full source lineage, conditions and explicit replacement/cancellation state. Enforce evidence coverage; recency alone cannot retire earlier conditions. |
| Permission changes after deduplication | Equivalence fingerprints include authority/policy/lifecycle. That is a safeguard, not an empirical proof of end-to-end privacy. V21 also repeats identical relationship-bearing IDs, independent of semantic equivalence. | Always suppress duplicate identical IDs; invalidate comparisons after policy changes; retain authorization before/after processing and at release. Test same-text facts under different readers/policies. |
| Whole-source deletion | Dependency reassessment is required. Historical recovery currently falsely treats live later source evidence as absent, suspending ownership. Broad failed-erasure holds block surviving facts. | Distinguish truly deleted evidence from evidence outside an old inference window. Reassess affected authority/current bindings; never restore an actual deleted value through recovery or deduplication. |
| Important fact exceeds context budget | Full-fact packing omits intact records; no identified missing requirement in the five failed V21 utility cases was established to be lost specifically at packing. Earlier extraction/scope/hold failures explain them. | Record pre/post-pack IDs and omission reason. Preserve atomic conditions, reserve relevant plan components and deduplicate before packing. Do not call the budget the cause without matching the exact fact. |
| Concurrent clients during a slow call | Single-registry service serialization remains an architectural limitation; these evaluation traces do not measure concurrent-client waiting. | Measure queue wait independently. Consider short state transactions plus versioned snapshot processing and final revalidation; never hold a DB transaction over a model call merely to serialize it. |
| Very large store | Candidate/grant enumeration grows; 24-pair review batches are expensive and backlog accumulates. Evolution currently stops for any quarantined job in the entire compartment, including recovered original jobs. | Reuse valid pair receipts, route by subject and necessary scope, index candidates, reconcile recovered-job state and schedule unaffected batches. Retrieval evolution must never rewrite permission checks. |
| Call longer than 30 seconds | V21 has no aggregate 30s cap. On the matched first 134 sources, 105 exceed 30s. Saved calls, not timer waits, dominate. | Benchmark the same backend for V19/V21, measure prefill/decode and output size, optimize repeated reviews. Keep durable retries and visible failures; an SLO is not permission to advance a failed source. |

These are observed failures, existing safeguards and proposed work, not a claim
that all fixes are implemented. Runtime code and the live run were unchanged by
this audit. See README.md and the individual checkpoint cards for exact evidence.
